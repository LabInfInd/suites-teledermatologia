# HTTPS su sisagen-cardio.poliba.it:11112

Configurazione preparata il 14 novembre 2026, non attivata nella VM. Il DNS A del
nome indicato risolve a 193.204.50.163. Il tentativo TCP verso la porta pubblica
11112 e andato in timeout dalla workstation: questo non dimostra che la porta sia
chiusa da ogni rete, per esempio se il rientro sul proprio IP pubblico e bloccato.
Verificare anche da una rete esterna, come la rete dati del telefono.

## Indirizzo previsto e percorso di rete

L app usera `https://sisagen-cardio.poliba.it:11112` come SUITES_API_BASE_URL.
Il certificato deve coprire il nome host; il numero di porta non entra nel nome
DNS o nel certificato. La porta pubblica 443 puo continuare a servire altri sistemi.

Il percorso da confermare con il referente di rete e:

```text
sisagen-cardio.poliba.it:11112 (TCP)
  -> inoltro pubblico/router e, se presente, PC 1
  -> 192.168.50.10:8443 (VM)
  -> gateway Caddy:443 (rete interna Docker)
  -> api:8000 (rete interna Docker)
```

La prima freccia non e stata verificata o creata. La disponibilita della porta
pubblica non implica che esista gia un inoltro alla VM. Se l inoltro esistente
arriva a una porta VM diversa da 8443, impostare HTTPS_VM_PORT di conseguenza,
dopo aver controllato che non sia usata da un altro servizio. Non inoltrare 11112
al servizio HTTP API:8000, altrimenti il collegamento non parla TLS.

## Certificato: la sola porta 11112 non basta per ACME standard

Un servizio HTTPS puo ascoltare su 11112, mentre le verifiche standard Let s Encrypt
HTTP-01 e TLS-ALPN-01 usano rispettivamente le porte pubbliche 80 e 443. Cambiare
la porta del servizio non sposta quelle verifiche su 11112. Le alternative sono:

- certificato pubblico valido per sisagen-cardio.poliba.it fornito dal referente IT;
- verifica DNS-01 tramite TXT `_acme-challenge.sisagen-cardio.poliba.it`, con chi
  amministra il DNS, o delega di quel record a una zona con aggiornamento automatico;
- instradamento concordato della verifica 80/443 sul servizio HTTPS gia esistente.

Questo profilo usa la prima possibilita oppure i file prodotti da un emettitore
DNS-01 esterno. Non configura un provider DNS sconosciuto e non promette rinnovi
automatici. L immagine caddy:2 standard non include tutti i plugin DNS dei provider.
Il vecchio compose.https.yaml resta il profilo ACME standard 80/443.

Non inviare chiavi private, password o token DNS in chat o su GitHub. Installare
sulla VM, tramite un canale amministrativo autorizzato, due file PEM:

```text
.local/tls/fullchain.pem   # certificato server seguito dagli intermedi
.local/tls/privkey.pem     # chiave privata corrispondente, leggibile dal servizio
```

La cartella .local e gia esclusa da Git e dal contesto Docker. Limitare i permessi
su directory e chiave all amministratore/servizio. La chiave non deve richiedere
una password interattiva all avvio del gateway. Il certificato deve essere
riconosciuto dai dispositivi Android/iOS previsti; un certificato autofirmato non
viene reso attendibile soltanto cambiando la porta. Non disabilitare la verifica
TLS nell app per aggirare errori di certificato.

Controlli preliminari sulla VM, quando i file saranno disponibili:

```bash
openssl x509 -in .local/tls/fullchain.pem -noout -checkhost sisagen-cardio.poliba.it
openssl x509 -in .local/tls/fullchain.pem -noout -checkend 604800
openssl verify -purpose sslserver -verify_hostname sisagen-cardio.poliba.it \
  -untrusted .local/tls/fullchain.pem .local/tls/fullchain.pem
python3 -c "import ssl; c=ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER); c.load_cert_chain('.local/tls/fullchain.pem','.local/tls/privkey.pem'); print('Certificato e chiave corrispondono')"
```

## Configurazione e attivazione quando rete e certificato sono pronti

Aggiungere nella .env gia esistente della VM, senza sostituire gli altri valori:

```dotenv
TELEDERM_DOMAIN=sisagen-cardio.poliba.it
TELEDERM_PUBLIC_HTTPS_PORT=11112
HTTPS_BIND_IP=192.168.50.10
HTTPS_VM_PORT=8443
TELEDERM_TLS_DIR=./.local/tls
```

Il profilo imposta per API/worker/migrazione l origine HTTPS completa di `:11112`,
COOKIE_SECURE=true e nessuna eccezione HTTP. L API rimane raggiungibile attraverso
il gateway; la sua porta diagnostica host diventa 127.0.0.1:8001. Il gateway espone
solo TLS su VM:8443. Questo passaggio sostituisce il precedente accesso HTTP alla
VM:8000: verificare l inoltro e conservare il rollback prima dell attivazione.

Dalla cartella server, dopo il backup previsto nella procedura di aggiornamento:

```bash
sudo docker compose -f compose.yaml -f compose.https-11112.yaml config --quiet
sudo docker compose -f compose.yaml -f compose.https-11112.yaml up -d --no-build
sudo docker compose -f compose.yaml -f compose.https-11112.yaml ps -a
```

Non combinare questo profilo con compose.https.yaml. Per controllare la VM prima
della prova esterna, usando DNS e certificato del nome scelto:

```bash
curl --resolve sisagen-cardio.poliba.it:8443:192.168.50.10 \
  https://sisagen-cardio.poliba.it:8443/health
```

Il controllo health deve rispondere 200 con certificato valido; non usare -k.
Da una rete esterna, verificare poi l indirizzo definitivo:

```bash
curl https://sisagen-cardio.poliba.it:11112/health
```

Dopo il login medico, catalogo, invio e mappe devono usare lo stesso host e la
stessa porta. Nessun token e richiesto per health; gli endpoint /v1 sono protetti.
L esempio mobile `mobile/config/server.sisagen.example.json` contiene soltanto
l URL non segreto. Dopo l attivazione del servizio si puo usare dalla cartella mobile:

```bash
flutter run --dart-define-from-file=config/server.sisagen.example.json
```

La prova finale deve includere un telefono reale. Per tornare al precedente
profilo HTTP usare `sudo docker compose -f compose.yaml up -d --no-build`,
conservando .env e volumi precedenti e dopo aver verificato i valori HTTP originali.

## Rinnovo

Con certificati installati manualmente l amministratore deve predisporre un rinnovo
prima della scadenza. Aggiornare in modo coerente fullchain e chiave, ripetere i
controlli e riavviare soltanto gateway con lo stesso profilo. Un processo DNS-01 puo
fornire i file automaticamente; il gateway deve poi ricaricarli. Non e stato
configurato un rinnovo in assenza di accesso al DNS/certificato dell istituto.

## Nomi gratuiti

DuckDNS offre gratuitamente sottodomini del tipo nome.duckdns.org, non la
proprieta di un dominio personalizzato. Un nome alternativo non apre la porta
11112 e non crea l inoltro alla VM. Il nome istituzionale gia disponibile evita
un ulteriore account o dipendenza esterna; si puo rivalutare DuckDNS se serve un
controllo DNS autonomo per l emissione del certificato, con autorizzazione del centro.

Fonti ufficiali:
- https://letsencrypt.org/docs/challenge-types/
- https://caddyserver.com/docs/automatic-https
- https://www.duckdns.org/about.jsp

## Controlli della configurazione preparata

Compose 5.7.1 ha validato l unione con compose.yaml sia per porta pubblica 11112
/VM 8443, sia per una coppia alternativa 11113/9443. Sono state controllate origine
con porta, cookie Secure, assenza di eccezioni HTTP e pubblicazione API solo sul
loopback. Caddy 2.11.9 ha analizzato il file con certificato esterno e automazione
ACME disabilitata. Gli strumenti sono stati scaricati dalle release ufficiali con
verifica SHA-256. Non sono stati caricati certificati reali, emessi certificati,
modificati DNS/inoltri o attivati servizi sulla VM.
